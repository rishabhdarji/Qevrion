# Qevrion status

Last updated: Round 5 (AR Walk) is built (28 Oct 2026) and waits for the owner's outdoor test on the iPhone, with one or two tuning passes expected. Round 4 (map and walking route) was accepted and merged on 28 Oct 2026. The project is on SDK 58. Version 0.0.1.

## What works

- Expo SDK 58 project (React Native 0.88, React 19.3) with TypeScript (strict) and Expo Router. Round 0 was confirmed on the iPhone in Expo Go on 10 Oct 2026, and the SDK 58 build on 27 Oct 2026.
- **Design system (Round 1).** `src/theme.ts` holds every colour, size, corner radius, type style and spring. Inter and Instrument Serif load at start-up. Components live in `src/components/`: `Screen` (optional top glow, pinned footer), `PrimaryButton`, `SecondaryButton`, `Pill`, `SectionLabel`, `Card` with `ListRow`, `EventHeroCard` (live countdown), `EventRow`, `StatGrid`, `Chip`, `EmptyState`, plus helpers `Txt`, `Icon`, `QevrionMark`, `SampleBadge`, `ScreenHeader`, `PressableScale`, `EventCover`, `Fade`, `StepBars`.
- **The Qevrion mark.** An open ring with a diagonal tail through the gap (option B, chosen by the owner). Source is `assets/mark.svg`; `npm run icons` redraws the app icon and launch image from it.
- **All ten screens.** Splash, onboarding (3 pages), Home with search and filter chips, Archive, event detail, add/edit, import (3 steps), Navigate, AR Walk, Settings. A component gallery opens from Settings, Developer.
- **A real database (Round 2).** Events and settings are stored on the phone in SQLite. `src/data/db.ts` is the only file that talks to it: numbered migrations, every field of SPEC section 7 for Event and Settings, and typed functions (`listEvents`, `saveEvent`, `deleteEvent`, `replaceSampleEvents`, `deleteSampleEvents`, `deleteAllData`, `getSettings`, `updateSettings`). Screens read and change events only through `src/data/events.ts` (`useEvents`, `useEvent`, `saveEvent`, `removeEvent` and the sample and delete-all actions), which keeps every event in memory.
- **Add, edit and delete an event.** The form saves. Start and end use the iPhone's own date and time picker, with an "All day" switch. A title is required and the end must come after the start; the message shows under the field. "Delete event" is at the bottom of the edit form and asks first.
- **Home and Archive read the database.** One flat list built by `src/lib/homeItems.ts`. The hero is the next event that has not started; it moves on the moment that event starts. Events under way sit under "Happening now" below the hero, then "This week", then months. Search and all five chips work on real data; "Has conflicts" finds events whose times overlap (`src/lib/conflicts.ts`; all-day events never count). An event moves to Archive the moment it ends. The app starts empty.
- **All-day events.** Stored as a calendar date, so the day does not shift with the time zone, and shown as "All day".
- **Onboarding is remembered.** It shows once; after that the app opens straight on Home with no splash wait.
- **Settings.** "Delete all data" removes every event and puts settings back to their defaults, after asking. Under Developer: "Insert 120 sample events" (each labelled "Sample"; pressing again swaps in a fresh set, never 240) and "Remove sample events" (leaves real events alone). Two of the samples start two and five minutes after they are inserted, so the hero can be watched moving on.
- **Event detail on real data.** Shows saved notes. Rows with nothing in them (no host, no description) are hidden. With no address there is no Navigate button, and an "Add a place" row says why and opens the form. A link typed into the form gets a button: "Open in Partiful" for a Partiful link, "Open link" for any other.
- **A photo for each event (Round 2b).** The add/edit form has a banner: "Add a photo" opens the iPhone's own photo picker, which asks for no permission; with a photo there the buttons are "Change" and "Remove". The photo shows behind the title on the event's screen and on Home's "Next up" card, under a darker fade so the title stays readable. List rows keep their date tile. The photo is copied into the app's own folder when the event is saved and never leaves the phone; it is deleted when it is replaced, removed, or its event is deleted, and all go with "Delete all data" (`src/data/photos.ts`).
- **Checks.** `npm run typecheck`, `npm run lint` and `npx expo-doctor` pass, and an iOS bundle exports cleanly. `npm run test:zones` runs all 304 tests in six time zones (UTC, New York, Kiritimati, Pago Pago, Lord Howe, Santiago), and CI runs the same on every push. The tests cover next-event selection, date grouping, all-day dates on every day of the year in each zone, conflicts, the form's rules, the sample generator, when a photo file is copied in and deleted, and the real SQL (schema, save, read, delete, settings, re-opening an existing database, and upgrading a database made before photos) run against the SQLite built into Node.

- **Navigate (Round 4).** A real Apple Maps card, dark and muted, with your position (green dot), the venue (red dot) and the walking route in blue, framed to show both. Under it: Leave by, Walking time, Distance, Event starts. The route comes from openrouteservice with the free key pasted in Settings; each route is kept on the phone (`routes` table, schema version 4) for two weeks and reused for a start within 75 m, so a day uses few of the key's 2,000 requests. A new route is only asked for when you are more than 40 m off the line, at most once every 30 seconds.
- **The fallback.** With no key, no connection, a refused key, a used-up quota, no route, or a venue too far to walk (over 30 km), Navigate shows a dashed straight line, the straight-line distance, the least time it can take ("14 min+"), Leave by, and the compass direction, with one line saying why. A kept route is still shown offline. "Open in Apple Maps" and "Open in Google Maps" are there in every case, including when the venue is not on the map.
- **Offline notice.** Navigate shows an amber "You're offline" banner the moment Wi-Fi and mobile data go off, and drops it the moment they are back (`expo-network`, in Expo Go). While offline no route is asked for; once back online the route is asked for at once instead of after the 30-second wait. The address list on the form says it is offline at once, without trying.
- **Location, just in time.** Nothing asks for location until Navigate is open for an event that is on the map; a card says why and has a "Use my location" button that puts the iPhone's question. "While using the app" only: `app.json` removes the background location strings. If you said no, the card leads to Settings; if Location Services are off for the phone, it says so. The GPS is followed only while Navigate is in front.
- **The route key.** Settings, Navigation, "Walking routes key" opens a screen that explains the free plan, links to sign-up, and takes the pasted key. It is checked with one test route between two fixed points in Heidelberg, then kept in the iPhone's keychain (`expo-secure-store`, this device only, readable while unlocked), never in SQLite. Shown as "ending abcd". "Delete all data" removes it and every saved route.
- **Units.** The Units row switches miles and kilometres; Navigate uses it.
- **Geo maths (`src/lib/geo.ts`).** Haversine distance, bearing, compass point, arrow rotation, nearest point on a route (with how far off and how far along), route length, waypoint advance at 15 m, walking time at 5 km/h, and distance and duration wording. Ready for AR Walk.
- **AR Walk (Round 5).** "Start AR Walk" on Navigate opens the rear camera full screen with an arrow laid on the ground (a flat dart and ring under a perspective transform, tipped to match how the phone is held). It points at the next turn of the walking route, or straight at the venue without one. On a straight street it aims at the turn; on a bending one at the furthest point it can aim at without cutting the bend by more than 8 m; within about 8 m of a corner it swings into the new street. The top card says "In about 120 ft" or "Now" and openrouteservice's instruction ("Turn right onto West 38th Street"); a turn counts as reached within 15 m, only while on the route, and stays on screen until 15 m past it. The bottom sheet has distance left, arrival time, the GPS and compass accuracy in plain words, and End. Two firm taps as a turn comes within 30 m; a success tap and "You've arrived" within about 25 m of the venue (or 15 m of the route's end), with "End walk" and "Keep guiding". A "Low accuracy" banner when GPS is worse than 30 m (gone again at 25 m) or the compass has been worse than 35 degrees for 3 seconds. A one-time safety note before the first walk. The screen stays awake while the walk is open. Camera, GPS, compass and motion sensor all stop when it closes, and pause while the app is in the background. Off the route by more than 40 m for 10 seconds asks for a new route (at most one per 30 seconds); this 10-second rule now applies on Navigate too. Without the camera the arrow sits on a drawn backdrop and a button turns the camera on.
- **Heading.** The arrow's heading comes from Apple's gyro-steadied device orientation (`expo-sensors` DeviceMotion, measured from magnetic north), turned into "the way the back camera looks" when the phone is upright and "the way the top points" when it lies flat, smoothly in between (`src/lib/heading.ts`). The compass (`expo-location` watchHeadingAsync) supplies true north less magnetic north, its calibration level, and the heading on its own if motion is missing. Smoothing is a one-euro filter worked the short way round the circle (steady when still, quick when turning), a 0.5-degree dead band, and a 90 ms animation per reading on the UI thread; the bearing to the aim eases over about a third of a second when it jumps. Readings never re-render the screen.
- **Simulate and record (Settings, Developer).** "Simulate AR Walk" replays a walk instead of following the GPS, with a "Simulated walk" bar: the event's own route walked at 5 km/h with GPS-like error and a poor stretch halfway (so the banner shows), or the last recorded walk; facing the way of the walk or the way the phone faces; 1x to 8x; restart. Navigate's button says "Start AR Walk (simulated)" while it is on. "Record AR walks" keeps the last real walk (GPS fixes, and both headings, the tilt and the compass level four times a second) in one file on the phone, for replay and to share for tuning from "Share the recorded walk". "Delete all data" removes it.
- **Address suggestions.** Typing three or more letters in "Where" on the add/edit form lists up to five matching addresses under the field; tapping one fills in the full address and keeps its coordinates, so it is "On the map" at once and never sent to Apple's geocoder. Nearby places come first when location is already allowed (the form never asks); without it suggestions still work. The list says where they come from and that what you type is sent there. Typing over a picked address drops its coordinates. Offline, it says so.

## Known issues

- **App icon and launch image are not visible in Expo Go.** Expo Go keeps its own home-screen icon and loading screen. The mark shows on the in-app Splash. The real icon and launch screen appear in the Round 10 standalone build.
- **Events live inside Expo Go for now.** Deleting Expo Go, or signing Expo Go in to a different Expo account, starts the app with an empty database. Whether data survives the move to SDK 58 is not known. Treat what is typed in as test data until the Round 10 standalone build.
- **Typed routes.** While the dev server is running it rewrites `.expo/types/router.d.ts` in a way that rejects template strings such as `` `/event/${id}` ``. Navigate to dynamic screens with the object form, `{ pathname: '/event/[id]', params: { id } }`, which always type-checks.
- **The desktop web preview runs on a stand-in, not the real database.** Expo's web version of SQLite is an alpha and cannot run this app (expo-sqlite 57.0.4, checked 11 Oct 2026): the dev server does not send the page the two cross-origin headers it needs, a synchronous call made before its worker has started times out, and any synchronous result longer than 255 bytes is cut short (`web/WorkerChannel.ts` writes the length into one byte). With the owner's agreement (11 Oct 2026) the preview uses `src/data/db.web.ts` instead, which keeps events and settings in memory, and `src/data/photos.web.ts`. Metro only picks `.web.ts` files for a browser, and the iPhone bundle was checked to contain none of it. What the preview shows is therefore the screens, not the database: the SQL is covered by the tests.
- **Round 2 works on the owner's iPhone (11 Oct 2026).** Not reported on specifically, so still unknown: the date picker at the largest text size; the app reloading itself when the phone's time zone changes; the guard for places where clocks change at midnight, which only an iPhone set to such a zone can exercise.
- **Address suggestions (Round 4).** Built with both free services behind one shape (`src/lib/suggest.ts`). Tried on 11 Oct 2026 with Photon: a street number with most of the street name finds the right address first, but the number alone, or with only the first letters of the street, does not. The Round 4 build machine could not reach Photon or openrouteservice at all (its network blocks both), and has neither the owner's key nor location, so the side-by-side test has to happen on the iPhone. Google's own suggestions need a billing account with a credit card. Apple's cannot run inside Expo Go; they become possible with the Round 10 standalone build.
- **Round 4 on the phone:** the map, the route, the location question, the offline banner and the address suggestions were all confirmed on the iPhone (19 and 27 Oct 2026). Not reported on specifically: the sign-up link landing on openrouteservice's form.
- **AR Walk heading, unconfirmed.** Apple documents the compass heading as the way the top of the phone points; nothing found says what it reports with the phone held upright for the camera. So the arrow uses the motion sensor's orientation instead, worked out from Apple's angle conventions (checked against the matrix WebKit builds from the same angles) but not yet seen on a phone. The developer line under the stats shows both numbers ("Motion 123° · Compass 125°") whenever Simulate or Record is on; if they disagree by a lot with the phone upright, that is the first thing to tune.
- **The desktop preview cannot follow a moving position.** expo-location 58's web `watchPositionAsync` replaces its own watch number with the browser's, so updates never reach the app (found 28 Oct 2026; `build/ExpoLocation.web.js`). The iPhone uses the native code and is not affected. Simulated walks do not depend on it, so the preview is still useful for AR Walk.

## Decisions

- **SDK 58 (27 Oct 2026).** The owner's Expo Go reports client 58.0.5, supported SDK 58.0.0, and so no longer opens SDK 57 projects. Moved to `expo` 58.0.19 and set every Expo-managed package to the version in that release's `bundledNativeModules.json` (`npx expo install --fix` could not be used: the build machine cannot reach the Expo API). npm refused the upgrade in place over an optional Windows-only peer of the date picker that is never installed, so `package-lock.json` was rebuilt from scratch; that also took `npm audit` from 67 findings to 5 (2 moderate, 3 high, all in build tools). Two type fixes for React Native 0.88, whose components are no longer classes: the onboarding scroller's ref is a `ScrollViewInstance`, and the tab bar's trigger ref is typed as a `PressableInstance` because expo-router 58 still types it as a class `View`. `expo-calendar/legacy` is unchanged. Gesture Handler moved to its 3.x line; the app does not use it directly.
- **SDK 57 (until 27 Oct 2026).** The App Store version of Expo Go was 57.0.9 and ran SDK 57 projects (Expo changelog, 3 Sep 2026, and the App Store listing).
- **Expo login is required.** Since Sep 2026, Expo Go on iOS only opens a project when the terminal (`npx expo login`) and the Expo Go app are signed in to the same Expo account. The free plan is enough.
- **Scaffold.** Started from the official `default@sdk-57` template, then removed its demo screens, components and Expo-branded images. Round 1 removed three unused template packages from `package.json` (`@expo/ui`, `expo-glass-effect`, `expo-device`).
- **Round 1 packages.** Added `react-native-svg` (mark, glow, covers, drawn map, arrow), `expo-haptics`, `@expo-google-fonts/inter` and `@expo-google-fonts/instrument-serif`; dev only: `jest`, `jest-expo`, `@types/jest`, `sharp`. Jest came one round early so the countdown and list logic are tested. Icons are SF Symbols through `expo-symbols`, which was already installed.
- **Fonts.** Imported one weight at a time (`@expo-google-fonts/inter/400Regular`), because the package's main entry pulls in all 18 files. Five font files are bundled.
- **Lists.** Home and Archive use React Native's built-in `FlatList` over one flat array. FlashList was considered and left out: at 100 to 150 rows it adds a dependency without a visible gain. The flat array is the shape FlashList wants, so switching later is small.
- **Gradients.** The top glow, covers and edge fades are single `react-native-svg` views. Never put an SVG in a list row; rows use plain coloured views. React Native's built-in gradient style was left alone because it is still marked experimental in 0.86, is renamed in 0.87, and draws nothing in the web preview.
- **Smoothness check.** Development mode is much slower than the real thing. To judge scrolling honestly, start with `npx expo start --no-dev --minify`.
- **Splash.** The in-app Splash holds for about a second, the first time only. Once onboarding has been seen the app opens straight on Home.
- **Mark at small sizes.** Beside the Home wordmark at 24 pt the mark read as a second search icon, directly above the real one. The Home and Archive headers now show the serif wordmark alone. The mark appears on the Splash, onboarding page 1, the icon, empty states and the Settings footer; under 32 pt its tail is drawn from the ring's centre (`QevrionMark.tsx`). This departs from the plan, which put the mark beside the wordmark: owner to confirm, and it is a one-line change to put back.
- **Dividers are 1 pt, not hairlines.** A hairline at 8% white nearly vanishes on a 3x iPhone screen.
- **Mock-ups must say so on the screen (owner feedback, 10 Oct 2026).** When testing Round 1 the owner took the drawn map and the AR Walk shell for broken features. A placeholder needs a plain caption on the screen itself, and a button that cannot do its job yet should either work in a simpler way or be named as a preview. A note in the plan is not enough.
- **Apple Maps link.** `src/lib/maps.ts` uses the older `?daddr=...&dirflg=w` link because Apple's newer `/directions?destination=` form needs iOS 18.4 and the app supports 16.4. Apple's server turns the old form into the new one, checked in a browser on 10 Oct 2026. Confirmed on the iPhone on 10 Oct 2026.
- **Round order changed (owner decision, 10 Oct 2026).** The map and AR Walk moved ahead of reminders and key details, and the rounds were renumbered to match: 2 database, 3 import, **4 map and walking route, 5 AR Walk, 6 reminders, 7 key details, weather and conflicts**, then 8 to 10 as before. The map cannot come before Round 3, which turns addresses into coordinates. Log book entries before number 75 use the old numbers (map 6, AR Walk 7, reminders 4, key details 5).
- **Google Maps (owner decision, 10 Oct 2026).** Navigate offers "Open in Google Maps" beside "Open in Apple Maps". It is a plain link (`src/lib/maps.ts`): no Google SDK, no key, no cost.
- **Storage design (Round 2).** SQLite is used through its synchronous calls, behind `src/data/db.ts`. Every event is read into memory once and re-read after each change, so no screen has a loading state and search never waits. This is sized for the app's few hundred events; with thousands, search and filtering would move into SQL. No ORM and no id library: the database makes its own ids.
- **Schema rules.** A migration is never edited once released; a schema change is a new entry in `MIGRATIONS`. Each runs in one transaction with its version number. Lists are JSON text. There are no checks on allowed values (`source`, `units`, `geocodeStatus`), because changing one later would mean rebuilding the table; the TypeScript types guard the only writer. `ScheduledNotification` is left for the reminders round as migration 2. Round 3's sync needs one more index, on `source` and `sourceId`. Version 2 (Round 2b) added `photo`, a file name. The importer's first schema change is entry 3, and a re-sync must leave `photo` alone, like notes.
- **All-day events are stored as midnight UTC on their calendar date**, with the end being the day after the last day. `src/lib/dates.ts` turns that into the phone's own day when read. `startOfDay` guards against a known fault in the iPhone's JavaScript engine in places where clocks change at midnight (Hermes issues 1121 and 2159).
- **Next-event rule.** The hero is the first event that starts after now. An event under way is listed under "Happening now", placed below the hero so that a string of all-day events cannot push the hero down the screen. Past means the end time has passed.
- **The clock.** `useEventClock` (`src/lib/countdown.ts`) wakes at the next start or end among the events, when the app returns to the front, and otherwise once a minute. The hero's own countdown ticks every second by itself.
- **Time zones.** Date formatters are built once and keep the zone the app started in, so `src/app/_layout.tsx` reloads the app if the phone's zone has changed when it returns to the front. Tests are written with local clock times so the same expectations hold everywhere, and `scripts/test-zones.mjs` runs them per zone; it sets the zone itself because a zone given on the command line does not reach Node in every shell.
- **Samples.** Sample events are ordinary rows whose `sourceId` starts with `sample:`. That is how they are labelled, replaced and removed without touching real events.
- **Design review of Round 2 (11 Oct 2026).** Applied: the first problem with the form is repeated beside the save button, because the form is taller than the screen; any typed link gets a button on the event; Settings rows that act on the spot have no arrow, and the two Developer actions are in the accent colour; "Delete all data" says the welcome screens come back; an event lasting a day or more names the day it ends; the search box says "Search events" when there are none. Judged right and left alone: the field order, the label above each picker, "Happening now" under the hero, the title field taking focus on a new event. Noted for Round 3: once multi-day events are imported, count only timed events as "Happening now" so they do not crowd "This week". Noted for later: closing the form throws away what was typed without asking.
- **Code that exists only for the desktop preview.** `src/data/db.web.ts` and `src/data/photos.web.ts` (see Known issues); any function added to `db.ts` or `photos.ts` needs its twin there, or the preview fails at once (never the phone). Two small branches: the form shows a date as text where there is no picker, and `src/lib/confirm.ts` asks through the browser where the app's own alert does nothing. The preview's one seeded event carries a drawn picture, because the browser's file picker cannot be worked from the preview.
- **Photos (Round 2b).** The database stores a photo's file name, not its address, because iOS moves the app's folder when the app is updated. A picked photo is copied in only on save, at reduced quality but full dimensions (shrinking would need another package), so expect 1 to 3 MB each. There is no cropping: the iPhone's crop tool only makes squares. Rows show no photos, to keep long lists cheap. A new photo is copied in before the event is written and the old one deleted after, so a failed save loses nothing; a crash between the two can leave one unused file behind.
- **Links.** The event screen only offers a button for a link that starts with `http://` or `https://`. Once events are imported a link is text from outside.
- **Security and speed checks for Round 2b (11 Oct 2026).** No keys or secrets in the code. Nothing new leaves the phone: the round adds no network call. No permission is asked for. The photo's file name is made by the app and only a short, plain ending is taken from the picked file. All SQL takes parameters; the few statements built from text use fixed lists in the code. `npm audit` is unchanged (0 critical, 50 high, 17 moderate, in build tools and one link parser, to be fixed by the SDK 58 upgrade) and the two new packages have no advisories. Speed: the image view shrinks a large photo to the size it is shown at, and the one-second countdown does not redraw the photo.
- **Source layout.** Screens live in `src/app/` (the template's layout). `@/` points at `src/`.
- **Design references** live in `design-refs/`, which is git-ignored. Notes are in `docs/DESIGN_NOTES.md`.
- **Design tokens (10 Oct 2026).** Lighter label grey `#85858D`: accepted. Top glow: partly accepted, subtle and not on every screen. Corner sizes chosen by the owner on a sample screen: cards 28, chips/tags/thumbnails 17, buttons fully rounded. These override SPEC section 6 (see `docs/DESIGN_NOTES.md`, Decisions).
- **Tunnel mode.** `@expo/ngrok` is a dev dependency, added by Expo when `npx expo start --tunnel` was run. Use `--tunnel` whenever the phone can't reach the PC over Wi-Fi.
- **Private working files.** The owner's standing rules and round-by-round build prompts live on the owner's PC and are deliberately not in this repo. `SPEC.md`, this file and `LOGBOOK.md` are the public record.
- **openrouteservice free plan (checked 19 Oct 2026).** Standard plan: Directions 2,000 a day and 40 a minute; Geocoding 3,000 a day and 100 a minute. Read from account.heigit.org/info/plans through search results, because the build machine's network could not open the page itself; the spec's 2,000 a day is still right. Autocomplete is not listed separately and is taken to count under Geocoding.

All three are in Expo Go on SDK 58 (checked against Expo Go's own package list for the SDK 58 release). `npm audit` is unchanged (2 moderate and 3 high, in build tools). `app.json` configures the camera's question for the later standalone build, with no microphone or barcode scanner, and turns off the motion question the sensors package would add (it is only for the step counter, which the app does not use).

## Round 3: import (accepted and merged 19 Oct 2026)

- **What it does.** Import screen: iPhone Calendar (pick calendars, each showing how many events it holds and how many are from Partiful; calendars with Partiful events are pre-ticked the first time), a fixed window of 30 days back to 12 months ahead, an "Only events with a partiful.com link" switch, and a result of Added, Updated, Unchanged, Skipped. Or an `.ics` file. Untick everything and "Stop reading calendars" lets calendars go; events already in stay.
- **Re-sync.** On every app open (at most once a minute) and on pull-to-refresh on Home and Archive. Matching is by calendar and event id (plus the original start for an occurrence of a repeating event), then by title and start within the calendars read. A sync never writes notes, checklist, tags, reminders, photo or key details.
- **Removed from calendar.** An event missing from a calendar that answered, inside the window, gets a notice and a "Removed" badge, and no longer counts for conflicts or the big card. A calendar that answers with nothing marks nothing. Deleting an imported event keeps only its key, title and times, so a sync does not bring it back.
- **Places.** Addresses of upcoming events are looked up with the iPhone's own geocoder (Apple Maps), one at a time, 1.5 s apart, only while the app is open. Each event shows "On the map", "Not found on the map" or "Not on the map yet". An address is asked once; samples, past and removed events, and anything containing a link are never sent.
- **Calendar files.** Up to 2 MB and 2,000 events. Repeating events in a file are left out and counted (the iPhone Calendar path brings repeats in). A file's own time-zone rules are used only when they are an ordinary daylight-saving pattern, because the parser can be made to loop forever otherwise. Parser: `ical.js` 2.2.1 (MPL-2.0, unmodified, zero dependencies; source at github.com/kewisch/ical.js).
- **Calendar package.** In SDK 57 the main `expo-calendar` entry point throws inside Expo Go; the app imports `expo-calendar/legacy`, which works there (confirmed on the iPhone with a temporary debug screen, since removed).
- **Schema version 3** adds `deletedAt` and a unique index on source + key; the upgrade drops a duplicate key first so it can never stop the app opening.
- **Reviews.** Two system-design and security reviews and one UI/UX review; every finding was fixed (freezing and oversized `.ics` files, links in addresses, deceptive links, control characters, look-alike matching, wording that promised nothing leaves the phone). 221 tests in six time zones.
