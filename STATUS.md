# Qevrion status

Last updated: Round 2 complete, confirmed on the iPhone in Expo Go (11 Oct 2026). Version 0.0.1.

## What works

- Expo SDK 57 project with TypeScript (strict) and Expo Router. Round 0 was confirmed on the iPhone in Expo Go on 10 Oct 2026.
- **Design system (Round 1).** `src/theme.ts` holds every colour, size, corner radius, type style and spring. Inter and Instrument Serif load at start-up. Components live in `src/components/`: `Screen` (optional top glow, pinned footer), `PrimaryButton`, `SecondaryButton`, `Pill`, `SectionLabel`, `Card` with `ListRow`, `EventHeroCard` (live countdown), `EventRow`, `StatGrid`, `Chip`, `EmptyState`, plus helpers `Txt`, `Icon`, `QevrionMark`, `SampleBadge`, `ScreenHeader`, `PressableScale`, `EventCover`, `Fade`, `StepBars`.
- **The Qevrion mark.** An open ring with a diagonal tail through the gap (option B, chosen by the owner). Source is `assets/mark.svg`; `npm run icons` redraws the app icon and launch image from it.
- **All ten screens.** Splash, onboarding (3 pages), Home with search and filter chips, Archive, event detail, add/edit, import (3 steps), Navigate, AR Walk, Settings. A component gallery opens from Settings, Developer.
- **A real database (Round 2).** Events and settings are stored on the phone in SQLite. `src/data/db.ts` is the only file that talks to it: numbered migrations, every field of SPEC section 7 for Event and Settings, and typed functions (`listEvents`, `saveEvent`, `deleteEvent`, `replaceSampleEvents`, `deleteSampleEvents`, `deleteAllData`, `getSettings`, `updateSettings`). Screens read and change events only through `src/data/events.ts` (`useEvents`, `useEvent`, `saveEvent`, `removeEvent` and the sample and delete-all actions), which keeps every event in memory.
- **Add, edit and delete an event.** The form saves. Start and end use the iPhone's own date and time picker, with an "All day" switch. A title is required and the end must come after the start; the message shows under the field. "Delete event" is at the bottom of the edit form and asks first.
- **Home and Archive read the database.** One flat list built by `src/lib/homeItems.ts`. The hero is the next event that has not started; it moves on the moment that event starts. Events under way sit under "Happening now" below the hero, then "This week", then months. Search and all five chips work on real data; "Has conflicts" finds events whose times overlap (`src/lib/conflicts.ts`; all-day events never count). An event moves to Archive the moment it ends. The app starts empty.
- **All-day events.** Stored as a calendar date, so the day does not shift with the time zone, and shown as "All day".
- **Onboarding is remembered.** It shows once; after that the app opens straight on Home with no splash wait.
- **Settings.** "Delete all data" removes every event and puts settings back to their defaults, after asking. Under Developer: "Insert 120 sample events" (each labelled "Sample"; pressing again swaps in a fresh set, never 240) and "Remove sample events" (leaves real events alone). Two of the samples start two and five minutes after they are inserted, so the hero can be watched moving on.
- **Event detail on real data.** Shows saved notes. Rows with nothing in them (no host, no description) are hidden. With no address there is no Navigate button, and an "Add a place" row says why and opens the form. A link typed into the form gets a button: "Open in Partiful" for a Partiful link, "Open link" for any other.
- **Checks.** `npm run typecheck`, `npm run lint` and `npx expo-doctor` pass, and an iOS bundle exports cleanly. `npm run test:zones` runs all 68 tests in six time zones (UTC, New York, Kiritimati, Pago Pago, Lord Howe, Santiago), and CI runs the same on every push. The tests cover next-event selection, date grouping, all-day dates on every day of the year in each zone, conflicts, the form's rules, the sample generator, and the real SQL (schema, save, read, delete, settings, re-opening an existing database) run against the SQLite built into Node.

## What is stubbed or missing

- **AR Walk has no camera, GPS or compass**; the arrow does not move (Round 5). The button that opens it reads "Preview AR Walk" until then.
- **"Open in Apple Maps" and "Open in Google Maps" work**: each opens walking directions to the event's address in that app (Google Maps falls back to its website if the app is not installed). Apple Maps was confirmed on the iPhone on 10 Oct 2026 and Google Maps on 11 Oct 2026.
- **Notes are edited in the form**, not on the event's own screen. The prep checklist is a picture shown on sample events only, with a caption; a real, stored checklist is Round 7.
- **Settings rows other than Data and Developer** (import sources, reminders, route key, units) are laid out but do not do anything yet. The database already has a place for each value.
- **The Developer buttons are visible to everyone.** They are not hidden in release mode, because the honest smoothness test runs in that mode. Hide them in Round 8.
- Key details, weather, reminders and the "tight gap" warning are absent or sample values (Rounds 6 and 7). Overlap detection is real.

## Known issues

- **App icon and launch image are not visible in Expo Go.** Expo Go keeps its own home-screen icon and loading screen. The mark shows on the in-app Splash. The real icon and launch screen appear in the Round 10 standalone build.
- **Events live inside Expo Go for now.** Deleting Expo Go, or signing Expo Go in to a different Expo account, starts the app with an empty database. Whether data survives the move to SDK 58 is not known. Treat what is typed in as test data until the Round 10 standalone build.
- **Typed routes.** While the dev server is running it rewrites `.expo/types/router.d.ts` in a way that rejects template strings such as `` `/event/${id}` ``. Navigate to dynamic screens with the object form, `{ pathname: '/event/[id]', params: { id } }`, which always type-checks.
- **The desktop web preview cannot run the app since Round 2.** Expo's web version of SQLite is an alpha and fell short in three ways (expo-sqlite 57.0.4, checked 11 Oct 2026): the dev server does not send the page the two cross-origin headers it needs; a synchronous call made before its worker has started times out; and any synchronous result longer than 255 bytes is cut short (`web/WorkerChannel.ts` writes the length into one byte), so reading more than about one event fails. The first two were worked around during Round 2 to check add, edit and delete against the real database in a browser; the third has no workaround short of patching the package, so the workarounds were removed again. Open question for the owner: add a preview-only stand-in for `src/data/db.ts` (a `db.web.ts` that keeps events in memory, never bundled for the iPhone) so screens can be checked on the PC before each phone test.
- **Round 2 works on the owner's iPhone (11 Oct 2026).** Not reported on specifically, so still unknown: the date picker at the largest text size; the app reloading itself when the phone's time zone changes; the guard for places where clocks change at midnight, which only an iPhone set to such a zone can exercise.
- **Asked for by the owner after Round 2 (11 Oct 2026), not built yet:** a photo or banner for each event, and address suggestions while typing in "Where".

## Decisions

- **SDK 57.** The App Store version of Expo Go is 57.0.9 and runs SDK 57 projects (Expo changelog, 3 Sep 2026, and the App Store listing). Expo's version-mismatch troubleshooting page still says the App Store stops at SDK 54; that page is out of date.
- **Expo login is required.** Since Sep 2026, Expo Go on iOS only opens a project when the terminal (`npx expo login`) and the Expo Go app are signed in to the same Expo account. The free plan is enough.
- **SDK 58 is in beta.** When it goes stable the App Store Expo Go will move to 58 and stop opening SDK 57 projects. Plan a short upgrade step when that happens.
- **Scaffold.** Started from the official `default@sdk-57` template, then removed its demo screens, components and Expo-branded images. Round 1 removed three unused template packages from `package.json` (`@expo/ui`, `expo-glass-effect`, `expo-device`).
- **Round 1 packages.** Added `react-native-svg` (mark, glow, covers, drawn map, arrow), `expo-haptics`, `@expo-google-fonts/inter` and `@expo-google-fonts/instrument-serif`; dev only: `jest`, `jest-expo`, `@types/jest`, `sharp`. Jest came one round early so the countdown and list logic are tested. Icons are SF Symbols through `expo-symbols`, which was already installed.
- **Fonts.** Imported one weight at a time (`@expo-google-fonts/inter/400Regular`), because the package's main entry pulls in all 18 files. Five font files are bundled.
- **Lists.** Home and Archive use React Native's built-in `FlatList` over one flat array. FlashList was considered and left out: at 100 to 150 rows it adds a dependency without a visible gain. The flat array is the shape FlashList wants, so switching later is small.
- **Gradients.** The top glow, covers and edge fades are single `react-native-svg` views. Never put an SVG in a list row; rows use plain coloured views. React Native's built-in gradient style was left alone because it is still marked experimental in 0.86, is renamed in 0.87, and draws nothing in the web preview.
- **Smoothness check.** Development mode is much slower than the real thing. To judge scrolling honestly, start with `npx expo start --no-dev --minify`.
- **Splash.** The in-app Splash holds for about a second, the first time only. Once onboarding has been seen the app opens straight on Home.
- **Mark at small sizes.** Beside the Home wordmark at 24 pt the mark read as a second search icon, directly above the real one. The Home and Archive headers now show the serif wordmark alone. The mark appears on the Splash, onboarding page 1, the icon, empty states and the Settings footer; under 32 pt its tail is drawn from the ring's centre (`QevrionMark.tsx`). This departs from the plan, which put the mark beside the wordmark: owner to confirm, and it is a one-line change to put back.
- **Dividers are 1 pt, not hairlines.** A hairline at 8% white nearly vanishes on a 3x iPhone screen.
- **Mock-ups must say so on the screen (owner feedback, 10 Oct 2026).** When testing Round 1 the owner took the drawn map and the AR Walk shell for broken features. A placeholder needs a plain caption on the screen itself, and a button that cannot do its job yet should either work in a simpler way or be named as a preview. A note in the plan is not enough.
- **Apple Maps link.** `src/lib/maps.ts` uses the older `?daddr=...&dirflg=w` link because Apple's newer `/directions?destination=` form needs iOS 18.4 and the app supports 16.4. Apple's server turns the old form into the new one, checked in a browser on 10 Oct 2026. Confirmed on the iPhone on 10 Oct 2026.
- **Round order changed (owner decision, 10 Oct 2026).** The map and AR Walk moved ahead of reminders and key details, and the rounds were renumbered to match: 2 database, 3 import, **4 map and walking route, 5 AR Walk, 6 reminders, 7 key details, weather and conflicts**, then 8 to 10 as before. The map cannot come before Round 3, which turns addresses into coordinates. Log book entries before number 75 use the old numbers (map 6, AR Walk 7, reminders 4, key details 5).
- **Google Maps (owner decision, 10 Oct 2026).** Navigate offers "Open in Google Maps" beside "Open in Apple Maps". It is a plain link (`src/lib/maps.ts`): no Google SDK, no key, no cost.
- **Storage design (Round 2).** SQLite is used through its synchronous calls, behind `src/data/db.ts`. Every event is read into memory once and re-read after each change, so no screen has a loading state and search never waits. This is sized for the app's few hundred events; with thousands, search and filtering would move into SQL. No ORM and no id library: the database makes its own ids.
- **Schema rules.** A migration is never edited once released; a schema change is a new entry in `MIGRATIONS`. Each runs in one transaction with its version number. Lists are JSON text. There are no checks on allowed values (`source`, `units`, `geocodeStatus`), because changing one later would mean rebuilding the table; the TypeScript types guard the only writer. `ScheduledNotification` is left for the reminders round as migration 2. Round 3's sync needs one more index, on `source` and `sourceId`.
- **All-day events are stored as midnight UTC on their calendar date**, with the end being the day after the last day. `src/lib/dates.ts` turns that into the phone's own day when read. `startOfDay` guards against a known fault in the iPhone's JavaScript engine in places where clocks change at midnight (Hermes issues 1121 and 2159).
- **Next-event rule.** The hero is the first event that starts after now. An event under way is listed under "Happening now", placed below the hero so that a string of all-day events cannot push the hero down the screen. Past means the end time has passed.
- **The clock.** `useEventClock` (`src/lib/countdown.ts`) wakes at the next start or end among the events, when the app returns to the front, and otherwise once a minute. The hero's own countdown ticks every second by itself.
- **Time zones.** Date formatters are built once and keep the zone the app started in, so `src/app/_layout.tsx` reloads the app if the phone's zone has changed when it returns to the front. Tests are written with local clock times so the same expectations hold everywhere, and `scripts/test-zones.mjs` runs them per zone; it sets the zone itself because a zone given on the command line does not reach Node in every shell.
- **Samples.** Sample events are ordinary rows whose `sourceId` starts with `sample:`. That is how they are labelled, replaced and removed without touching real events.
- **Design review of Round 2 (11 Oct 2026).** Applied: the first problem with the form is repeated beside the save button, because the form is taller than the screen; any typed link gets a button on the event; Settings rows that act on the spot have no arrow, and the two Developer actions are in the accent colour; "Delete all data" says the welcome screens come back; an event lasting a day or more names the day it ends; the search box says "Search events" when there are none. Judged right and left alone: the field order, the label above each picker, "Happening now" under the hero, the title field taking focus on a new event. Noted for Round 3: once multi-day events are imported, count only timed events as "Happening now" so they do not crowd "This week". Noted for later: closing the form throws away what was typed without asking.
- **Web fallbacks kept.** Two small ones remain for the day the desktop preview works again: the form shows a date as text where there is no picker, and `src/lib/confirm.ts` asks through the browser where the app's own alert does nothing.
- **Source layout.** Screens live in `src/app/` (the template's layout). `@/` points at `src/`.
- **Design references** live in `design-refs/`, which is git-ignored. Notes are in `docs/DESIGN_NOTES.md`.
- **Design tokens (10 Oct 2026).** Lighter label grey `#85858D`: accepted. Top glow: partly accepted, subtle and not on every screen. Corner sizes chosen by the owner on a sample screen: cards 28, chips/tags/thumbnails 17, buttons fully rounded. These override SPEC section 6 (see `docs/DESIGN_NOTES.md`, Decisions).
- **Tunnel mode.** `@expo/ngrok` is a dev dependency, added by Expo when `npx expo start --tunnel` was run. Use `--tunnel` whenever the phone can't reach the PC over Wi-Fi.
- **Private working files.** The owner's standing rules and round-by-round build prompts live on the owner's PC and are deliberately not in this repo. `SPEC.md`, this file and `LOGBOOK.md` are the public record.
- **Credits.** Commit messages and pull requests carry no tool credit or co-author lines, at the owner's request.
- **Preview.** A local preview config (kept out of git) attaches the desktop preview to a dev server that is already running on port 8081. Start the server yourself with `npx expo start` first. Since Round 2 the preview cannot run the app; see Known issues.
- **Git.** Work happens on `round-N-short-name` branches and merges to `main` after the round is confirmed on the phone.
- **GitHub.** `main` is pushed to the public repo `rishabhdarji/Qevrion`. The repo was recreated on 10 Oct 2026 so that a cleaned history could be pushed fresh; local branches should never need a force-push. Commits use GitHub's private noreply address, set in this repo's local git config; the owner's personal email must stay out of commits. The owner's standing instruction is to push `main` at each important milestone without asking each time, after checking nothing private is in the commits. Never force-push.
- **CI.** `.github/workflows/ci.yml` runs `npm ci`, type-check, lint and the tests in six time zones on every push.
- **Privacy audit (10 Oct 2026).** Everything public was checked and found clean. Follow-ups applied: `.gitignore` ignores all `.env*` files, `*.ics`, `*.db`, `*.sqlite`, `*.ipa`, `*.cer` and `*.keystore`; CI has read-only permissions. Round 3 must add a `.gitignore` exception for its invented `.ics` test fixtures. The owner has turned on GitHub's "keep my email private" and "block pushes that expose my email" settings. Still open for the owner: the PC's global git email is the personal address (only this repo is set to noreply); local backup refs under `refs/original/` hold pre-rewrite commits and must never be pushed (do not use `git push --mirror`).
- **Time zone stays private.** Commit with the `TZ` environment variable set to `UTC` so timestamps carry no local offset. Keep local clock times out of every public file, and write dates as UTC dates. `LOGBOOK.md` has no clock times for this reason.
- **Devices.** The app must work on every iPhone that can run Expo Go (iOS 16.4 or later) at any screen size, not one model. Whether iPad or Android should be supported is an open question for the owner; Android is in the spec's backlog and Google Maps on Android would need a key.
- **README.** `README.md` has a roadmap table. Update its Status column, and the "Early days" note, each time a round is confirmed.
- **CD.** Nothing to deploy yet. Planned: site to GitHub Pages (Round 9), unsigned `.ipa` build (Round 10).
